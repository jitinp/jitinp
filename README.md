## What I'm Building

**[Software Factory](https://lfg.run)** · [lfg-hq/lfg-factory](https://github.com/lfg-hq/lfg-factory)
Takes a request from scope all the way to a verified pull request. Product manager agent → architect agent → developer agent → QA agent, coordinated through an orchestration layer, wired into a team's own repos, trackers and models. Runs on their infrastructure or ours. In pilot with IT services firms of 100-200 people.

**Mags Instance Sandboxes**
Secure sandboxed execution environments for AI agents. Firecracker microVMs on a bare metal cluster, no nested virtualization, with persistent storage via JuiceFS/S3. Snapshot/restore gets cold starts under 500ms, and every agent gets its own isolated runtime. 90+ concurrent sandboxes per 12-core host.

**Mags Self Deploy**
Draw your stack on a canvas, point it at servers you own. Each app builds in a disposable sandbox and deploys with HTTPS, databases and rollbacks. No platform lock-in.

**[Kitereach](https://kitereach.com)**
An AI content studio. On-brand reels, short films and carousels from a website and a sentence, with script and look approved before anything renders.

**Easylogs**
Hosted log search, server metrics and alerting for small engineering teams, with an agent that answers questions by running real queries against the logs.

## What I Think About

I write a lot about the shift from traditional software development to agentic workflows: how background agents, sandboxed execution, and AI orchestration are reshaping what it means to build software. Most of that lives on [LinkedIn](https://www.linkedin.com/in/jitinp/).

The short version: we're moving from developers-who-use-AI-tools to AI-agents-who-use-developer-tools. The infrastructure layer (runtimes, state persistence, secure execution) is what makes that real.
